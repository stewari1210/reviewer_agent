## Domain Reference Guidelines
* **DMPK/PMx Context:** Pay special attention to parameter identifiability, scaling assumptions (allometry vs. physiological scaling), and covariate modeling logic.
* **Multi-Agent Context:** Ensure clear separation of concerns among specialized sub-agents. Verify that the orchestrator/router logic is sound and mathematically grounded. Watch specifically for validation that measures a deterministic downstream model's accuracy while claiming to validate the LLM/agent layer itself — this was the central issue in manuscript 1958167 and is a pattern worth checking for in any future agent-orchestration submission.
* **Physiological Constants / Model Reference (from 1958167, for continuity if resubmitted or cited by future manuscripts):**
  - Chen et al. PBPK model (refs 16, 24) — multi-layer stratum corneum / viable epidermis / dermis discretization; note refs 16 and 24 are different first authors (Chen T vs Chen L), not interchangeable.
  - Jouyban-Acree cosolvency relation: log Sc = log Sw + sigma*fc, sigma = M*logKow + N (cosolvent-specific M/N; must be reported per-compound to be checkable).
  - Vehicle-water partition: Pv/w = fc*(Sc/Sw7) + fo*Dow^n, with n=0.8 used in 1958167 without cited justification — flag if reused unchanged in a later submission without derivation.
  - ESOL (Delaney) solubility equation: documented to be unreliable for small, fully water-miscible solutes (e.g., lactic acid, MW ~90) — relevant applicability-domain caveat for any future submission using RDKit/ESOL Step-1-style property estimation on similar compounds.
  - Evaporation sub-module (Deacon et al., ref 37): gated on finite-dose + unoccluded exposure classification.

  * **Status:** Initial review completed 2026-09-25 (full report: 1978548_Review.md)
  * **Domain:** Agentic-AI tool grounding / genome-writing design infrastructure (not DMPK/PMx) — first review in this sub-domain; general multi-agent evaluation criteria from 1958167 carried forward and applied.
  * **Key Focus Areas Requested:** Default scope — multi-agent state management, tool-use logic, hallucination guardrails, deterministic/stochastic boundary evaluation; biosecurity screening relevance.
  * **Prior Flags:**
    - Fabrication-rate benchmark confounds "agent declined to answer" with "agent grounded its answer" — 3 of 12 tool-driving runs made zero tool calls and passed by non-engagement (Table 4, footnote d), not disclosed in the abstract's headline "fabricated nothing" claim.

    - Load-bearing expression-robustness axis validated at ρ=0.571 only at exact-site chromatin resolution; collapses to ρ≈0.16 at the coarse 1-kb resolution the platform serves by default — flagged at runtime (outcome_validated=false) but underemphasized in the manuscript's own framing.
    - Deployed genotoxicity safety net is a static blocklist of 8 already-documented clinical loci; the learned writability score it backstops missed 3/8 (37.5% false-negative rate) of those same loci — no protection against a genuinely novel insertional-oncogenesis site.
    - No multiple-comparisons discussion across the large number of correlation/AUROC claims underlying the 10 pre-registered verdicts.
    - Frozen/immutable no-fabrication guarantee is type-level only; explicitly does not resist a caller with direct Python/code-execution access (object.__setattr__ bypass) — a real residual risk if this library is ever co-located with a code-executing agent, under-discussed relative to the paper's own biosecurity framing.
  * **Positives worth remembering:** genuinely strong typed/frozen-result + claim-vs-candidate state-management pattern; unusually candid reporting of 8/10 pre-registered claims not passing, surfaced as machine-readable flags rather than smoothed over — good model for reproducibility/pre-registration practice to hold other agentic-biology submissions to.

## Domain Reference Guidelines (continued)
* **Agentic-AI / Genome-Writing Context:** When a submission claims a grounding/no-fabrication architecture reduces hallucination, check specifically whether the "grounded" condition is doing the same task as the ungrounded baseline, or whether it is allowed to abstain/decline — abstention silently inflates apparent success in fabrication-style benchmarks. Also check whether the adversarial benchmark used to support the claim was built independently of the team that built the system, per the pattern identified in 1978548.
* **Genotoxicity/safety-screening components:** A static documented-loci blocklist is a completeness guarantee, not a generalizable predictor — flag this distinction explicitly whenever a submission's safety net for insertional oncogenesis (or similar irreversible-harm domains) relies on a fixed reference list rather than a validated generalizing model.

## Domain Reference Guidelines (continued)
* **Recurring cross-manuscript pattern (now confirmed across all three reviews to date):** a headline comparison or ablation result turns out, on inspection, to measure a confounded quantity rather than the specific architectural claim under test — 1958167's validation measured the pre-existing PBPK model's accuracy rather than the LLM orchestration layer's classification accuracy; 1978548's fabrication-rate benchmark conflated grounding success with non-engagement/abstention; 2607.07666's GHCP baseline conflates architecture with tool-access/scaffolding differences. When reviewing any future agentic-science submission, check specifically for this pattern first: does the reported benchmark actually isolate the paper's stated novel contribution, or does it measure something upstream/downstream of it that would look the same either way?
* **Guardrail-effectiveness benchmarking:** when a submission claims physics-based/domain checklists or PI-review layers catch implausible outputs, check whether the paper quantifies a catch rate (as in 1978548's 8/8 biosecurity screen and fabrication-rate tables) or only describes the mechanism qualitatively (as in 2607.07666) — the latter is weaker evidence and worth flagging, especially if the manuscript's own reported results contain an example of exactly the failure the guardrail should have caught.

* **Revision-handling pattern (from 1958167 round 1):** authors' response letters may arrive before the revised manuscript; check manuscript_responses for the full revised text (re-list the folder, the PDF may land later) and say so explicitly when only a letter is present. Treat "we have revised accordingly" without reported numbers or section content as unverified, not as closed. Always re-verify the response letter against the revised text: letter claims (e.g. 'added variability to Table 5', 'primary literature source') did not fully match the manuscript.
* **Agent-eval benchmark pattern (1958167 revision):** when authors add an agent-layer evaluation in response to critique, check (a) who authored/generated prompts (template-generated + developer-labelled = ceiling effect), (b) model identity/config/repeat runs, (c) CIs on perfect scores, (d) whether every classification axis named in Methods is actually scored, (e) field-count denominators, (f) whether the LLM is doing arithmetic that belongs in deterministic code, (g) whether disclosed failures map onto the exact scenario the Methods claim is guarded.
* **Recurring author tendency (1958167):** Abstract/Conclusion language lags body-text corrections; check headline claims after revisions.

* **Lesson (1958167):** in round 1 I missed reproducibility-of-the-LLM items (model identity, exact components, PBPK settings) and the CRediT gap that another reviewer caught. For any LLM-orchestration submission, check reproducibility specifics (exact model/version/prompts/schemas/settings, 'A or B' component lists, solver versions) in the FIRST review, not after revision.
